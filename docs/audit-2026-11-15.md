# Accessibility and performance audit — rann-xyz.github.io/hbd

Date: 2026-11-15. Target: the live deployment, commit `0784328`
("fix: a thumb is not a cursor, and 9.9px is not a size").

Method: Chromium 145 headless driven over CDP at 390x844, DPR 3, mobile emulation.
Contrast ratios computed in-page by compositing each text node's colour over its
effective background (walking ancestors, resolving alpha), against WCAG 2.1 AA
thresholds (4.5:1 normal, 3:1 large). Load metrics from PerformanceObserver
(largest-contentful-paint, layout-shift, longtask, paint) plus the Navigation
Timing and Resource Timing APIs, with CDP network and CPU throttling.

Nothing below was fixed. No commit, no push.

---

## A. Accessibility

### A1. FAIL — the countdown live region speaks every second (serious)

`.sr-only[aria-live="polite"][aria-atomic="true"]` is rewritten every ~990ms.
Measured: 7 updates in 6 seconds; 5 updates in 5 seconds while the countdown
section was scrolled off-screen.

    Time left until your birthday: 1 day, 15 hours, 40 minutes, 52 seconds
    Time left until your birthday: 1 day, 15 hours, 40 minutes, 51 seconds
    ...

A polite live region that changes every second makes the page unusable with a
screen reader: it queues an announcement per second and talks over every other
element the user moves to.

Fix: announce only when the value is worth announcing — the minute changing, or
once when the section is entered — or drop `aria-live` and put the value in the
grid's accessible name so it is available on demand.

### A2. FAIL — the cake banner is unreadable: 1.63:1 (WCAG 1.4.3)

`.cake__banner` ("Happy Birthday, Fitria", 24px, `--font-hand`) resolves to
`color: var(--rose-ink)` = `rgba(197, 143, 153, 0.55)` over the cream page.

    ratio 1.63:1   needs 3:1 (large text)

`tokens.css` already documents this exact rule and this exact trap:

    --rose-ink:     rgba(197, 143, 153, 0.55);
    /* Dusty rose is a fill colour: as *text* it reads at 2.6:1. This deeper
       rose carries the handwritten voice at 4.9:1. */
    --rose-text:    #965F6B;

The banner is the only text element in the whole stylesheet that uses the fill
token. Every other use is a border, stroke or ornament:

    base.css:379        border-bottom-color (nav link underline)
    layout.css:145      .opening__orn (aria-hidden ornament)
    layout.css:233      .portrait__bow (svg container)
    layout.css:243      .site-foot__sprig (ornament)
    layout.css:340      .closing__bloom (svg container)
    components.css:89   border-bottom dashed (hand link)
    components.css:1046 .cake__banner  <-- text

Fix: `color: var(--rose-text)`.

### A3. PASS, but fragile — `.stamp__label` at 4.55:1

11.5px uppercase tracked caps on the stamp's own paper (251,241,233). Needs 4.5.
0.05 of headroom. (Before commit `0784328` this was 8.8px, so the type-floor fix
lifted it here.)

### A4. PASS — contrast sweep

37 distinct text styles on the landing state, 42 with the letter open, 39 with
the cake lit and a wish saved. Zero failures other than A2.

### A5. PASS — structure

- Exactly one `h1`; one `h2` per section; `h3` inside; no level skips.
- Landmarks: `header` (banner), `nav aria-label="Sections"`, `main`, `footer`
  (contentinfo); every section is `aria-labelledby` its own heading.
- 28 focusable elements, every one with an accessible name.
- All 30 decorative SVGs are `aria-hidden="true" focusable="false"`.

### A6. PASS — the letter dialog

`role="dialog"`, `aria-modal="true"`, `aria-labelledby` set. Focus moves into the
dialog on open, Tab stays inside, Escape closes it (verified with a real CDP key
dispatch, not a synthetic `KeyboardEvent`), and focus returns to the envelope.

### A7. PASS — focus is visible

`2px solid rgb(138, 91, 102)`, `outline-offset: 3px` on nav links, the candle,
buttons and note toggles.

### A8. PASS — reduced motion

Under `prefers-reduced-motion: reduce` every transition collapses to 0.001s, no
animation runs, and all 32 reveal elements stay fully visible — nothing is left
stranded at opacity 0.

### A9. PASS — reflow and text resize

No horizontal page overflow at 320 / 360 / 375 / 390 / 414 / 430 / 600 / 768 /
1024 / 1280 / 1440. At 200% text resize (`html { font-size: 32px }`) there is
still no page-level overflow; the only `scrollWidth > clientWidth` hits are the
nav's 44px hit-area pseudo-elements (exactly 8px = 2 x 4px `inset-inline`), i.e.
false positives.

### A10. MINOR — the one photograph is announced twice, differently

    #portrait img  alt="Portrait of Fitria Cahaya Aulia"
    #closing  img  alt="Fitria Cahaya Aulia, photographed once and kept"

Same file (`assets/fitria-portrait.jpg`), both visible. Either description is
defensible on its own, but a screen reader user hears the single photograph
described two different ways.

### A11. NOTE — `aria-current="true"`

Valid, but `aria-current="location"` is the more precise token for a section nav.
Cosmetic.

## B. Performance

### B1. The webfonts are ~7x the app code

Three families requested in one Google Fonts URL: Cormorant Garamond (30 declared
faces), DM Sans (8), Caveat (12) — 50 `@font-face` rules, 13 of them latin.

    Google Fonts CSS      20,063 B decoded / 1,315 B transferred
    Caveat woff2          74.9 KB   (decoded, as fetched by the browser)
    Cormorant Garamond    39.3 KB
    Cormorant Garamond    37.6 KB
    DM Sans woff2         62.7 KB
    ------------------------------
    fonts                 ~214.5 KB

    app JS                20,835 B transferred (61,054 B decoded)
    app CSS                8,709 B transferred (34,646 B decoded)

Independently confirmed with curl against the latin woff2 URLs: Caveat 400 =
72.8 KB, Cormorant Garamond 300/400 = 38.4 / 36.9 KB, DM Sans 400 = 61.1 KB.

So: ~215 KB of type against ~30 KB of application.

### B2. The request declares more weights than the CSS uses

    used in the stylesheets   DM Sans 400, 500
                              Cormorant Garamond 300, 400, 400 italic
                              Caveat 400
    requested                 Cormorant Garamond 300, 400, 500, 600,
                              300 italic, 400 italic
                              DM Sans 300, 400, 500, 400 italic
                              Caveat 400, 500, 600

Unused declarations cost no font bytes (the browser fetches only the faces it
needs) but they do inflate the 20 KB Google CSS, which is render-blocking.

### B3. LCP is the H1, and the font is what delays it

    LCP element   H1.display "A LITTLE WORLD MADE FOR YOU"  (41,595 px^2)
    LCP          2,888 ms   (Slow 4G, cold cache)
                 3,556 ms   (Slow 4G, cold cache, second run)
                 2,256 ms   (unthrottled, cold cache)

    Slow 4G (1.6 Mbps / 150 ms RTT), cold cache:
      TTFB 82-344 ms | FCP 1,024-1,088 ms | domComplete 2,759-4,086 ms

Both stylesheets sit in `<head>` and are render-blocking, and the H1 waits for
Cormorant Garamond to arrive over a second connection to fonts.gstatic.com (h3).

Candidate fixes, cheapest first:
1. `<link rel="preload" as="font" type="font/woff2" crossorigin>` for the two
   latin faces that paint above the fold.
2. Trim the Google Fonts URL to the weights actually used (cuts the blocking CSS
   from ~20 KB to ~3 KB).
3. Self-host the 3-4 used faces — removes the second origin entirely.

### B4. PASS — layout stability

CLS 0.0001-0.0002 across every run; no layout-shift entries recorded at all.
`display=swap` is doing its job.

### B5. Long tasks

    unthrottled cold load   5 long tasks, ~837 ms total, worst 531 ms at 795 ms
    opening the surprise    1 long task, 79 ms

(The raw observer output double-counted each entry because the instrumentation
script was injected more than once; the figures above are de-duplicated.)

### B6. Cache

GitHub Pages serves `cache-control: max-age=600` on every asset — HTML, CSS, JS
and images alike. Ten minutes. A revisit after that window refetches the ~215 KB
of fonts plus the app. Not fixable on Pages without moving host; noted, not a
defect of the site.

### B7. Assets

    fitria-portrait.jpg   56,627 B, 720x1280, rendered 336x584 CSS px @3x  -> appropriate
    og-cover.png         457,822 B, 1200x630, served 200 image/png
    favicon.svg              579 B

The OG card is within every platform's limit but a JPEG or WebP would be 4-5x
smaller for the same card.

## C. Not verified

- No real device. Everything above is Chromium 145 headless at 390x844 with
  emulated DPR, CDP network throttling and (attempted) CDP CPU throttling. No
  iOS Safari, no Firefox, no real Android WebView.
- No screen reader was run (NVDA / JAWS / VoiceOver / TalkBack). A1 is inferred
  from the DOM mutation rate of the live region, not from hearing it.
- No Lighthouse, no axe, no third-party audit tool. Every number here is from my
  own instrumentation.
- The 4x CPU throttle measurement failed — the harness IPC timed out at that rate
  and had to be reset. Long-task figures are unthrottled.
- The `?cb=` / cache-busting runs are not a true first-visit measurement of the
  font payload: the browser's font cache survives `Network.clearBrowserCache`, so
  the woff2 sizes in B1 come from the one run where they appeared in Resource
  Timing, cross-checked with curl.
